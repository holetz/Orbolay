## Problem

Reproduced by the epic 13 review: `grep -n "sha\|hash\|checksum\|timeout" crates/orbolay-rtt/src/stt/models.rs` → no output. `fetch()` streams the body to disk and renames it into place (`crates/orbolay-rtt/src/stt/models.rs:66-84`); HTTPS only (`:11`), no pinned checksum, no timeout. Consequence: a wrong-but-200 body (error page) or tampered file is fed to whisper.cpp's native parser; a stalled server hangs the download forever.

## Proposal

- A downloaded model is accepted only if its SHA-256 equals the pinned digest for that model; a mismatch deletes the partial file, never renames it into place, and returns an error naming the model.
- All six `KNOWN_MODELS` carry a pinned digest, and a test fails if a known model has none.
- The download has a connect timeout and a response timeout, so a stalled server ends in an error instead of hanging the settings button forever.

## Out of Scope

- Verifying models the user placed by hand in the models directory: they have no pinned digest, and the user owns them.
- Resuming interrupted downloads and a progress bar: a separate UX concern.
- Mirrors or a signed manifest: the pins are compiled in; the source is the Hugging Face LFS oid.

## Impact

### Product code this spec expects to touch

- `crates/orbolay-rtt/src/stt/models.rs` - pins, hash check, timeouts
- `crates/orbolay-rtt/Cargo.toml` - adds `sha2`
- `Cargo.lock` - lock entry for `sha2`

## Validation

- `cargo test -p orbolay-rtt models` passes, including the new `corrupt_download_is_rejected` test; run against the pre-fix `models.rs` (without `verify_sha256`) it does not compile or fail.
- `cargo fmt --all -- --check && cargo clippy --workspace -- -D warnings && cargo test --workspace` exit 0, and the same with `--features rtt` for clippy and test.
- No default test touches the network.

## Design

- Pins live in `fn expected_sha256(model) -> Option<&'static str>`, keyed by the name without `.bin`. A model without a pin cannot be downloaded: `download` returns an error rather than skipping the check (fail closed).
- Source of every pin: the `lfs.oid` field (SHA-256) returned by `https://huggingface.co/api/models/ggerganov/whisper.cpp/tree/main`, fetched 2026-10-11; recorded in Discoveries.
- `verify_sha256(path, expected)` streams the file through `sha2::Sha256` in 64 KiB chunks (models reach 487 MB; never read whole into memory) and compares hex case-insensitively.
- The hash is checked on the `.bin.part` file before the rename, so the final path only ever holds verified bytes.
- Timeouts through a `ureq::Agent` built with `timeout_connect` 15 s, `timeout_recv_response` 30 s and a generous `timeout_recv_body` of 30 min (ureq 3 has no per-read timeout; the body bound is total).
- Contract kept: `download(model) -> Result<PathBuf, String>` signature unchanged for `orbolay-ui`.

## Alternatives Considered

- Fetch the digest from the same host at download time: rejected, a tampered host serves a matching digest.
- Skip hashing and rely on HTTPS plus Content-Length: rejected, does not catch a wrong-but-200 body of the right length nor a compromised upstream.

## Open Decisions

- none - the timeout values are tunable constants, decided here (15 s / 30 s / 30 min).

## Risks

- Upstream replaces a model file, so the pin rejects a good download: ACCEPTED - the error names the model and a new pin is a one-line change; failing closed is the point.
- 30 min total body bound cuts off a very slow link on the 487 MB model: ACCEPTED - ~270 KB/s suffices; the user can retry.
