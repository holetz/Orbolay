## Problem

`rtt-stt-engine` (spec 4) ships with `ggml-base` as a provisional default model. The real default
must come from measuring latency and CPU for `tiny`/`base`/`small` while a game is running. That
needs a GPU, a game session and live speech, which a Linux-only autonomous agent does not have.
Gathered here from `rtt-stt-engine` task 3.2 (source `specs/plans/rtt-stt-engine.md`).

## Proposal

- With a game running, measure time-to-first-caption and Orbolay's CPU use for `tiny`, `base` and
  `small`.
- Record the numbers in ## Discoveries and set the default `rttModel` accordingly.

## Out of Scope

- GPU acceleration sub-features (`rtt-cuda`, etc.); out of scope in spec 4 too.
- Changing the engine or VAD. Findings that call for that become discoveries for a follow-up spec.

## Impact

### Product code this spec expects to touch

- `crates/orbolay-core/src/config.rs`: the default of `rttModel`

## Validation

- Manual: with a game running, captions appear within ~3 s, and CPU use of the Orbolay process is
  recorded for `tiny`/`base`/`small` in ## Discoveries. Default chosen accordingly. (Moved from spec
  4's ## Validation.)
- `cargo fmt --check && cargo clippy --workspace --features rtt -- -D warnings && cargo test --workspace --features rtt` passes after the default changes.

## Design

- Decision rule, from spec 4's open decision: the largest model that keeps Orbolay under ~15% of
  one core on average during conversation on a mid-range CPU.

## Alternatives Considered

- none — the measurement itself is the decision procedure spec 4 already chose.

## Open Decisions

- Which machine counts as "mid-range". Decided by the human at measurement time and recorded with
  the numbers, so the default can be re-judged later.

## Risks

- CPU/GPU cost while gaming makes the feature unusable even with `tiny` (epic 1 Risks). Mitigation:
  record it, keep `rttThreads` configurable, and raise it with upstream before spec 12.

## Handoff

- Runs after spec 4 (`rtt-stt-engine`, epic `rtt`) is merged into `develop`.
- Model files live under the Orbolay config dir (`crates/orbolay-core/src/dirs.rs`).
