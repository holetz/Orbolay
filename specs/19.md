## Problem

Reproduced by the epic 13 review: six 10 ms clicks each followed by 400 ms silence, then flush → `[3] segments (utterance, is_final): [(1, false, 24000, 0ns)]` — a provisional segment and no final. `close()` returns `None` when voiced audio < `min_speech` 250 ms (`crates/orbolay-rtt/src/stt/vad.rs:181`), yet a provisional was already emitted after 1.5 s (`vad.rs:167-174`); the pipeline only removes a line on an empty final (`crates/orbolay-rtt/src/pipeline.rs:236`). Consequence: noise (keyboard clicks) leaves a partial, possibly hallucinated caption on the panel forever.

## Proposal

- An utterance that emitted a provisional segment always ends with a final segment, even when its voiced audio is below `min_speech`; that final carries no samples and means "discard".
- The pipeline removes the caption line for a discard final without calling the engine.
- Noise (keyboard clicks) can no longer leave a provisional caption on the panel forever.

## Out of Scope

- Changing `min_speech`, the partial cadence or the noise-floor logic: the thresholds are right, the missing close-out is the bug.
- Adding a new field to `AudioSegment` (owned by `stt/mod.rs`): an empty-sample final already encodes the discard.
- Expiring stale partial lines by timer: rejected, the final is the single authority on a line's fate.

## Impact

### Product code this spec expects to touch

- `crates/orbolay-rtt/src/stt/vad.rs` — `close()` emits an empty final for a dropped utterance that had a provisional.
- `crates/orbolay-rtt/src/pipeline.rs` — the engine loop handles the discard final.

## Validation

- `cargo test -p orbolay-rtt --features capture vad::tests::dropped_utterance` exits 0 and runs the new test (it must fail on the pre-fix code: the reproduction yields a provisional and no final).
- `cargo test -p orbolay-rtt --features capture pipeline::tests::discard` exits 0.
- Gate from `.claude/CLAUDE.md`, including the `--features rtt` variants.

## Design

- Rule: every utterance id that appeared in a provisional segment is closed by exactly one final segment. A final with empty `samples` is a discard; the engine never sees it.
- Utterance numbering stays the process-wide counter from spec 18; ids are untouched, so the removal by `mic-<id>` / `loopback-<id>` cannot hit another line.
- The VAD tracks `partial_sent` per utterance; `close()` returns the real final when voiced audio is sufficient, an empty final when it is not but a partial was sent, and `None` otherwise (a click that never reached a partial leaves no line, so nothing to remove).
- Pipeline: the line id is built in one helper shared by `transcript_line` and the discard path. Discard runs before `engine.transcribe`, so no hallucinated text can resurrect the line.

## Alternatives Considered

- Transcribe the short utterance anyway and let the empty-text path remove it: rejected, it hands noise to the engine, which can hallucinate text and keep the caption.
- Suppress the provisional until `min_speech` voiced audio exists: rejected, it delays real captions and the voiced count can still fall short at close.

## Open Decisions

- none — the discard encoding (empty final) is decided above.

## Risks

- A consumer treating an empty final as speech: ACCEPTED — the only consumers are the job queue (passes it through) and the engine loop, which this spec updates.
- Queue overflow dropping a discard final: finals are never dropped by the queue (verified by the existing overflow test), so the line is always removed.
