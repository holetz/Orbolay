## Problem

Reproduced by the epic 28 review (`target/quenching/review3/dl`, `fetch` + connector copied byte-for-byte from `crates/orbolay-rtt/src/stt/models.rs:132-242`, ureq 3.4.2): `review3-dl https://huggingface.co/ggerganov/whisper.cpp/resolve/main/README.md` → `Err("TLS required, but transport is unsecured") after 0.0s`; the same with only `fn is_tls(&self) -> bool { self.inner.is_tls() }` added → `Ok(()) after 0.2s size=Ok(3196)`. Spec 27's `impl Transport for ClampedRead` (`models.rs:169-190`) does not forward `is_tls`, so ureq's default `false` (ureq `src/unversioned/transport/mod.rs:311`) trips `needs_tls() && !is_tls()` (ureq `src/run.rs:407-408`). Consequence: `BASE_URL` is HTTPS (`models.rs:21`), so the settings UI's model download fails for every known model — no model can be installed. The tests missed it because every download test uses plain `http://`. Fix: forward `is_tls` (and audit the other `Transport` defaults for the same omission), with a network-free regression test that fails when the wrapper reports a TLS inner transport as unsecured.

## Proposal

- `ClampedRead` reports TLS exactly when its inner transport does, so an HTTPS download through `PerReadTimeout` no longer fails with `TLS required, but transport is unsecured`.
- Every other defaulted `Transport` method in ureq 3.4.2 is audited and the decision recorded; only those whose default would be wrong through the wrapper are forwarded.
- A network-free regression test fails when the wrapper reports a TLS inner transport as unsecured.

## Out of Scope

- Changing the stall/timeout behaviour of specs 25/27: unrelated, must keep passing.
- Adding an HTTPS test server or a live-network test to the suite: flaky and offline-hostile; the wrapper-level test covers the omission.

## Impact

## Validation

- `cargo test -p orbolay-rtt --features capture clamped_read` passes, and fails on the pre-fix code with an assertion that the wrapper reported `is_tls() == false`.

- Optional one-off: a scratch (uncommitted) binary fetching `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/README.md` returns Ok.

## Design

- Rule: a `Transport` wrapper forwards every defaulted method whose default answers a question about the inner connection. `is_tls` is such a method (default `false`, checked by ureq `run.rs` as `needs_tls() && !is_tls()`).
- Audit of ureq 3.4.2 defaulted methods: `is_tls` forwarded. `maybe_await_input` is NOT forwarded: its default checks `buffers().can_use_input()` then calls `self.await_input`, which is the clamped override; forwarding to the inner would bypass the clamp (the spec 27 fix). `boxed` is a `Self: Sized` constructor helper and is not a connection property.
- Test: a fake inner `Transport` built with `ureq::unversioned::transport::LazyBuffers`, returning `is_tls() == true`, wrapped in `ClampedRead`; assert the wrapper's `is_tls()` is true.
- Alternative weighed: an offline HTTPS handshake through ureq; rejected as needing certificates and a server for a one-line forward.

## Alternatives Considered

- Replace the wrapper by a ureq config timeout: ureq 3.4.2 has no per-read timeout, which is why spec 27 introduced the wrapper.

## Open Decisions

- none — the fix and the audit are fully determined by the ureq source.

## Risks

- A future ureq adds another defaulted method that matters: mitigated by the audit note in `## Design` naming the rule.
- The fake transport's `LazyBuffers` constructor differs from expectation: ACCEPTED — a compile error would surface it immediately.
