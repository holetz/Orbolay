## Problem

On the human's machine (XDG_SESSION_TYPE=wayland, WAYLAND_DISPLAY=wayland-0, DISPLAY=:0), the installed `develop` build 642fcf3 (`--features rtt`) segfaults within a second of start when `~/.config/orbolay/config.json` has `"xwayland": true`: `timeout -s INT 6 orbolay` → exit 139 ("Falha de segmentação"), last log line the Wayland warning. The same binary with `"xwayland": false` runs, connects over IPC and handles VOICE_STATE_UPDATE events (exit 124 on timeout). The only effect of the flag is `std::env::set_var("WAYLAND_DISPLAY", "")` at `src/main.rs:127-128`, which forces the X11 path. Note `Config::default()` sets `xwayland: true` (`crates/orbolay-core/src/config.rs:213`) while a missing key deserializes to `false` (`#[serde(default)]` at `:144`), so a config written by the configurator on first run enables the crashing path. Consequence: the README's advice ("will probably not work correctly unless running with XWayland") leads straight to a crash. Next: get a backtrace (`coredumpctl gdb` or `RUST_BACKTRACE=1` + gdb), check whether upstream main crashes the same way, and whether `--features rtt` matters.

## Discoveries

- 2026-10-11 diagnosis (gdb, target/quenching/xwayland/): on XWayland the transparent window falls through Vulkan ('no transparent composite alpha') and GLX (BadAlloc) to EGL, and eglCreatePlatformWindowSurface segfaults inside NVIDIA libnvidia-egl-xlib.so.1 (driver 595.99) — freya_winit drivers/gl.rs:207. Not rtt-related (default-features build crashes too). Correction: config.rs:144 is serde(default = "default_true"), so a missing key also enables xwayland. Workarounds that run: FREYA_RENDERER=software (config softwareRendering: true), __GLX_VENDOR_LIBRARY_NAME=mesa, Mesa EGL vendor. Proposed fix: on wayland session + xwayland, force software renderer unless explicitly overridden (or only on NVIDIA); default xwayland false at config.rs:144/:213; update README advice.
