## Problem

Reproduced by the epic 13 review: `local_path("../../evil") = ~/.config/orbolay/models/../../evil.bin` and `url=https://huggingface.co/ggerganov/whisper.cpp/resolve/main/../../evil.bin`, `known? false`. The name is joined onto the models dir unchecked (`crates/orbolay-rtt/src/pipeline.rs:30-40`), `download()` never checks `KNOWN_MODELS` (`crates/orbolay-rtt/src/stt/models.rs:59-65`), and the settings button passes the config's `rttModel` through (`crates/orbolay-ui/src/configurator/mod.rs:572-580`). Consequence: a crafted config value writes `<name>.bin`/`.part` outside the models dir and requests a `../`-relative URL.

## Proposal

- A model name that is not a bare file name (separators, `..`, empty) never yields a path or a URL: `model_path` returns `None` for it.
- `download` accepts only names in `KNOWN_MODELS` (with or without `.bin`) and returns a clear `unknown model` error otherwise, before touching disk or network.
- The settings UI shows that error in the existing model status line; an unknown `rttModel` already in a config never panics or crashes the app (the pipeline sees an empty model path and reports the missing model as it does today).
- A regression test proves `../../evil` yields no path, no download and no file outside the models dir.

## Out of Scope

- Removing support for extra `.bin` files the user dropped into the models dir: they stay selectable (bare names only), because `available_models` already lists them. Only download is restricted to `KNOWN_MODELS`.
- Rewriting an invalid `rttModel` in the saved config: the value is left untouched and merely reported.

## Impact

### Product code this spec expects to touch

- `crates/orbolay-rtt/src/pipeline.rs` — `model_path` boundary check
- `crates/orbolay-rtt/src/stt/models.rs` — `download` known-name check, regression tests
- `crates/orbolay-ui/src/configurator/mod.rs` — show the rejection and the not-installed state for an invalid name

## Validation

- `cargo test -p orbolay-rtt --features capture` passes, including the new regression tests; run against pre-fix code they fail (recorded in Outcome).
- Gate from `.claude/CLAUDE.md`: `cargo fmt --all -- --check && cargo clippy --workspace -- -D warnings && cargo test --workspace`, plus the `--features rtt` clippy and test variants.

## Design

- Rule: a model name is valid for path building only if it is a single normal path component (after an optional `.bin`); an existing file path given as `rttModel` keeps working as is (read-only use, no write or URL derived from it).
- Rule: downloading is allowed only for `KNOWN_MODELS`; the check sits in `download` itself so every caller is covered, and the UI just surfaces the `Err`.
- `local_path`, `is_installed` and `download_url`-based flows go through `model_path`, so they inherit the boundary; `download_url` is only reached after the known check.
- Assumption: user-added `.bin` files in the models dir are a supported feature (`available_models` lists them), hence the component check instead of known-only for lookup.

### Mapa de dependências

- `model_path` is called by `PipelineConfig::from_config` (pipeline.rs) and `models::local_path`; `local_path` by `is_installed`, `available_models`, `download`; `download` and `is_installed` by configurator/mod.rs only. A `None` from `model_path` already degrades to `unwrap_or_default()` in the pipeline.

## Alternatives Considered

- Known-only lookup for every name: rejected, it would orphan the user-added models `available_models` lists.
- Validating only in the UI: rejected, the config file is the attack surface and `download` is public.

## Open Decisions

- none — the assumptions are named in Design.

## Risks

- A legitimate model name containing a separator would now be refused: ACCEPTED, `rttModel` names are bare file names and full paths to existing files still work.
- Pipeline with an empty path for an invalid name: handled as today's missing-model case; the test covers it does not panic.
