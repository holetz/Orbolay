## Problem

The RTT work must reach `SpikeHD/Orbolay` as **one** pull request containing only product code.
That needs a sync with upstream, a full manual validation matrix (Linux IPC and websocket,
Windows and macOS hardware), a single-commit export branch, a PR on upstream and force-pushes during
review. `.claude/CLAUDE.md` forbids PRs on upstream from automation, and the hardware checks need a
human. Gathered here from epic section 3 (tasks 3.1 to 3.5) and the manual bullets of epic 1 and
spec 6 (source `specs/plans/rtt-epic.md`, `specs/plans/rtt-capture-windows-macos.md`).

## Proposal

- Sync `main` with `upstream/main` and merge `main` into `develop`.
- Run the full validation matrix.
- Export a single-commit `feat/rtt` branch from `upstream/main` with only product code.
- Write the PR description, push `feat/rtt` to `origin`, open the PR to `SpikeHD/Orbolay:main`.
- Address review on `develop`, re-export and force-push `feat/rtt` until merged or declined.

## Out of Scope

- New product work. Review changes are made on `develop` through the owning child spec or a new one.
- Anything if upstream declines in spec 8: this spec is then skipped (epic 1 Open Decisions).

## Impact

### Product code this spec expects to touch

- none — it exports what epic `rtt` merged; review fixes land through other specs.

## Validation

- Manual end-to-end on Linux (official client, IPC mode): join a voice channel with 2+ people,
  enable captions; lines appear within ~3 s of speech, labelled with the correct names; your own
  speech is labelled with your name; panel scrolls and fades as configured. (From epic 1.)
- Manual end-to-end in websocket mode (Vencord/shelter bridge): same result. (From epic 1.)
- Manual on Windows 11: Discord call captions work, and game audio isn't transcribed when process
  loopback is available. (From spec 6.)
- Manual on macOS 14 (Apple silicon): permission prompt appears once, then captions work. (From
  spec 6.)
- `git diff upstream/main...feat/rtt --stat` shows no path under `specs/` or `.claude/`, and
  `git rev-list --count upstream/main..feat/rtt` is `1`. (From epic 1.)

## Design

- Follows epic 1's branch model: `feat/rtt` is cut from `upstream/main`; the product diff
  `git diff upstream/main develop -- . ':!specs' ':!.claude' ':!.gitignore'` is applied and committed
  once, with the `.gitignore` hunk dropped by hand if it's the only change there.
- Force-push only ever targets `origin/feat/rtt`, never `main` or `develop`.
- The PR description explains design choices in the human's own words (CONTRIBUTING.md item 6).

## Alternatives Considered

- Several PRs, one per child spec. Rejected by epic 1: upstream reviews one coherent change.

## Open Decisions

- Whether to include the CI job (spec 11) in the export. Decided by spec 8's answer.

## Risks

- Specs or `.claude/` leak into the upstream diff. Mitigation: the export pathspec plus the
  `git diff --stat` check in ## Validation.
- Upstream drifts during review. Mitigation: re-sync (task 1.1) before each re-export.
- LLM-assisted code rejected as "slop". Mitigation: line-by-line human review (epic 1 Risks).

## Handoff

- Runs last: after every member of epic `rtt` (specs 2 to 6) and specs 8 to 11 are done.
- Upstream: https://github.com/SpikeHD/Orbolay; fork: https://github.com/holetz/Orbolay.
