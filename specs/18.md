## Problem

Reproduced by the epic 13 review (harness `target/quenching/review/`): `[2] transcript after restart: [("mic-1", "after restart"), ("mic-2", "before restart B")]`. Each new VAD segmenter restarts utterance numbering at 1 (`crates/orbolay-rtt/src/stt/vad.rs:90`), the line ID is `"{source}-{utterance}"` (`crates/orbolay-rtt/src/pipeline.rs:282`), the controller rebuilds the pipeline on every settings change (`src/main.rs:494`) without clearing the transcript, and a push with an existing ID replaces in place (`crates/orbolay-core/src/transcript.rs:26`). Consequence: toggling captions or changing model/language/device overwrites visible old lines; an empty final deletes an old line (`pipeline.rs:236-237`).

## Proposal

- Utterance numbers are unique for the life of the process, so a pipeline rebuilt by a settings change never reuses a caption line ID already in the transcript.
- A regression test shows two successive `VadSegmenter` instances never emit the same utterance id.

## Out of Scope

- Clearing the transcript on pipeline restart: would drop history the user still sees; the ID fix keeps it.
- Changing the `"{source}-{utterance}"` ID format in `pipeline.rs`: unique utterance numbers already make it unique.

## Impact

### Product code this spec expects to touch

- `crates/orbolay-rtt/src/stt/vad.rs` — utterance counter becomes process-wide

## Validation

- `cargo test -p orbolay-rtt vad` passes; the new test fails on the pre-fix code.
- Gate from `.claude/CLAUDE.md`, including the `--features rtt` variants, exits 0.

## Design

- Decision: a process-wide `static AtomicU64` (starting at 1, `fetch_add` relaxed) supplies utterance ids, replacing the per-segmenter `next_id`. Rule: an utterance id is unique within the process, not within a segmenter. Mic and loopback segmenters share the counter; their IDs still carry the source prefix, so this only widens uniqueness.
- Per-decision alternative: the pipeline stamps a generation number into the ID; rejected as more plumbing for the same effect.
- Assumption: the paths named in the Problem under `crates/` are the real locations (`orbolay-core/src/transcript.rs` needs no change).

## Alternatives Considered

- Clear the transcript on every pipeline rebuild: loses visible history on a mere settings toggle.
- Make `push_capped` generation-aware: touches the core crate for a producer-side bug.

## Open Decisions

- none — the fix is fully determined by the evidence.

## Risks

- Tests that assumed ids start at 1 may break; mitigation: the new counter is read relative to the first id in tests.
- ACCEPTED — ids are no longer deterministic across tests running in one process; no production code depends on the value.
