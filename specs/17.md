## Problem

Since PR #3 (merge 102d3fb), `crates/orbolay-rtt` is a workspace member (`Cargo.toml:2`) whose
`cpal = "0.17"` and `alsa = "0.11"` are unconditional (`crates/orbolay-rtt/Cargo.toml:10,16`).
`cargo clippy --all` / `--workspace` therefore compiles `alsa-sys` even without `--features rtt`,
and needs `libasound2-dev`. Upstream `.github/workflows/check.yml:44` installs no ALSA package and
runs `clippy --all` (`:50`). Consequence: once exported, the RTT PR breaks upstream's Check job,
and it contradicts epic 13's design promise that the `rtt` feature keeps heavy deps out of default
builds. Fix candidates: drop `orbolay-rtt` from `members` (it stays a path dep), or put its audio
deps behind a crate feature, so default `--workspace` builds never link ALSA. Workflows are not edited.

## Proposal

- A default `cargo build/clippy/test --workspace` compiles none of `alsa-sys`, `cpal` or `whisper-rs-sys`.
- `--features rtt` still builds, lints and tests the full capture stack.
- A regression test fails if the default dependency graph ever contains those crates again.
- The README RTT section no longer says the workspace build needs ALSA.

## Out of Scope

- Editing CI workflows, hooks or `.claude/settings*`: upstream owns them.
- Removing `orbolay-rtt` from `members`: rejected, a path dependency is a workspace member regardless (checked with `cargo tree`).

## Impact

### Product code this spec expects to touch

- `crates/orbolay-rtt/Cargo.toml` — heavy deps optional behind a `capture` feature
- `crates/orbolay-rtt/src/lib.rs` — modules gated on `capture`
- `Cargo.toml`, `crates/orbolay-ui/Cargo.toml` — `rtt` features enable `orbolay-rtt/capture`
- `Cargo.lock` — only if resolution changes
- `tests/default_graph.rs` — regression test
- `README.md` — RTT section

## Validation

- `cargo tree --workspace -e normal | grep -E 'alsa-sys|cpal|whisper-rs-sys'` prints nothing (exit 1).
- `cargo tree --workspace -e normal --features rtt` lists all three.
- Gate: fmt check, `clippy --workspace -D warnings`, `test --workspace`, plus the same with `--features rtt`.

## Design

Rule: heavy native deps of `orbolay-rtt` sit behind its own `capture` feature; the crate's modules are `cfg(feature = "capture")`. The root and UI `rtt` features enable `orbolay-rtt/capture`. Without it `orbolay-rtt` is an empty lib, so the workspace stays whole and consumers need no changes.

### Mapa de dependências (2026-10-11)

- `src/main.rs:479` and `crates/orbolay-ui/src/configurator/mod.rs` use `orbolay_rtt::*` only under the `rtt` feature, which now enables `capture`.
- The rtt example and the `transcribe` test require `capture`.

## Alternatives Considered

- Drop from `members`: no effect, path deps are implicit members.
- `exclude`: still listed by `cargo tree --workspace`.
- Separate nested workspace: loses `workspace = true` deps and workspace test coverage.

## Open Decisions

- none — the approach was settled by evidence (alternatives tested).

## Risks

- A future dependency added outside `capture` reintroduces ALSA; the regression test catches it.
- ACCEPTED — the rtt crate's own unit tests run only with `--features rtt`, since they need the gated modules.
