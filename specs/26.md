## Problem

Reproduced by the epic 24 review (harness `target/quenching/review2/e2e`, public `MonoResampler` + `VadSegmenter`): 1 s silence, a jump to 5000 ms, speech at 5500 ms → `rate 48000 ch 2: speech really starts at 5500ms; final utt 1 start=1.24s end=3.57s`; VAD alone: `speech at ~5.64s; final start=520ms`. Spec 20 (PR #7) re-anchored the resampler's output timestamps, but `crates/orbolay-rtt/src/stt/vad.rs:103` only reads `frame.timestamp` when `pending` is empty and `vad.rs:112` otherwise advances by window count; at 48 kHz the resampler emits ~342 samples per frame against a 480-sample window, so a partial window is almost always pending. The wrong `segment.start` feeds attribution at `crates/orbolay-rtt/src/pipeline.rs:245`. Consequence: spec 20's harm persists in the real 48 kHz path — after a queue drop every loopback segment is stamped early by the dropped time (~4.3 s) and matched to the wrong Discord speaker. Test end to end (resampler → VAD), not the resampler alone.

## Proposal

- After a forward input-timestamp gap, `VadSegmenter` stamps segment starts from the input frame's timestamp even when a partial window is pending.
- An end-to-end regression test (48 kHz stereo, `MonoResampler` into `VadSegmenter`) reproduces the Problem and fails on the pre-fix code.

## Out of Scope

- Closing an open utterance at the gap: the resampler already discards its tail, and spec 18/19 behaviour (process-wide utterance ids, empty final on a dropped provisional) is kept unchanged.
- Any change to `MonoResampler` (spec 20) or to `pipeline.rs` attribution: the wrong start came from the VAD, so the pipeline needs no edit.

## Impact

### Product code this spec expects to touch

- `crates/orbolay-rtt/src/stt/vad.rs` — gap detection in `push` and the regression tests.

## Validation

- `cargo test -p orbolay-rtt --features capture segment_start_reanchors` must pass; on the pre-fix code it failed with `speech really starts at 5500ms; final start=1.24s`.
- Gate per `.claude/CLAUDE.md`, including the `--features rtt` variants, exits 0.

## Design

- Rule: `push` computes where the pending samples end (`pending_start + duration(pending)`); a frame starting more than one analysis window later discards the partial window and re-anchors `pending_start` to the frame. An empty buffer still anchors to the frame.
- Tolerance of one window (30 ms) is assumption-based: resampler timestamps are sample-exact, so normal jitter is far below it.

## Alternatives Considered

- Re-anchor only when `pending` is empty (the old rule): fails at 48 kHz, where a partial window is nearly always pending.
- Zero-pad the partial window up to the gap: invents audio and delays nothing useful.

## Open Decisions

- none — the tolerance is fixed at one window; revisit only if a capture source shows jitter beyond it.

## Risks

- A source with timestamp jitter above one window would drop a partial window (under 30 ms of audio) spuriously. ACCEPTED — the resampler emits sample-exact timestamps.

## Outcome

Shipped: `VadSegmenter::push` in `crates/orbolay-rtt/src/stt/vad.rs` now re-anchors its clock when a frame starts later than the pending samples' end plus one window (an input timestamp gap): the straddling partial window is discarded and `pending_start` is set to the frame.
