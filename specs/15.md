## Problem

`develop` still tracks the quenching v4.12 file-store scaffold: `specs/QUENCHING.md`,
`specs/schema.json`, `specs/templates/spec.md`, `specs/archive/.gitkeep`, `specs/plans/.gitkeep`
(`git ls-files specs`). Since 5c66a14 the store is `backend: git` (branch `quenching`), yet
`specs/QUENCHING.md:68` and `:109` still tell any reader that a spec lives in `specs/plans/<slug>.md`
and moves to `archive/`. Consequence: an agent or human following the tracked manual writes specs
into a folder nothing reads. Fix: delete the scaffold, keeping only `specs/plans/README.md`'s
pointer (moved to `specs/README.md`), and run the gate.

## Proposal

- `git ls-files specs` lists only `specs/README.md`.
- `specs/README.md` carries the pointer to the `quenching` branch store (content of the old `specs/plans/README.md`).
- No tracked file tells a reader that specs live in `specs/plans/` or `specs/archive/`.
- The gate passes.

## Out of Scope

- Editing CI workflows, hooks or `.claude/settings*`: not touched by this deletion.
- Migrating or rewriting specs in the `quenching` store: unrelated to the tracked scaffold.

## Impact

### Standards this spec will write into docs/standards/

- none — a scaffold deletion declares no standard.

### Product code this spec expects to touch

- `specs/QUENCHING.md`, `specs/schema.json`, `specs/templates/spec.md`, `specs/archive/.gitkeep`, `specs/plans/.gitkeep` — deleted
- `specs/plans/README.md` — moved to `specs/README.md`

## Validation

- `git ls-files specs` prints only `specs/README.md`.
- `cargo fmt --all -- --check && cargo clippy --workspace -- -D warnings && cargo test --workspace` exits 0.

## Design

- Delete rather than rewrite the manual: the store is `backend: git`, so the tracked v4.12 manual is dead and misleading. Rewriting it would keep a second source of truth.
- Keep the pointer README at `specs/README.md`, since the old path `specs/plans/` is the one being retired.

### Mapa de dependências

Evidence (2026-10-11): a repo-wide grep for `specs/QUENCHING`, `specs/schema`, `specs/templates` and `specs/plans` outside `target` and `.git` matched only `specs/QUENCHING.md` itself. Nothing else references the files, so nothing breaks or is orphaned.

## Alternatives Considered

- Rewrite `specs/QUENCHING.md` for the git store: rejected, duplicates what `cq` documents and would drift again.
- Leave the scaffold and only fix lines 68 and 109: rejected, the remaining files are still dead.

## Open Decisions

- none — the evidence answers every item.

## Risks

- A tool still reading `specs/schema.json` could break: mitigated by the grep showing no reference, and by the gate. ACCEPTED for any external tool outside the repo, since the store no longer uses the file.
